# Trigger evaluation cases

These cases test whether the `description` activates the skill for documentation work without capturing nearby writing or explanation tasks. Run each case several times across the target agents. Record whether the agent loaded `write-good-docs` before answering.

## Should trigger

1. “Can you clean up `README.md`? It rambles and the setup steps are buried.”
2. “Document the authentication flow from the code and tests in this repository.”
3. “Turn these issue notes into an ADR. Keep the decision and consequences clear.”
4. “Shorten this incident runbook without losing any safety checks.”
5. “Review the prose in our API reference and fix ambiguous parameter descriptions.”
6. “Add useful docstrings to the public methods in `client.py`; don't narrate obvious code.”
7. “Write a migration guide for moving from schema v2 to v3.”
8. “We added `--dry-run` to the CLI. Update the user guide and command reference.”
9. “This onboarding page was generated by AI and is painfully repetitive. Make it sound human.”
10. “Write a design doc for moving session storage from local memory to PostgreSQL.”
11. “Make this troubleshooting page easier to follow from the error message.”
12. “Create docs for this feature. The audience is support engineers, not developers.”

## Should not trigger

1. “Explain this regular expression to me in chat.”
2. “Draft an email announcing the new API.”
3. “Write a LinkedIn post about why good documentation matters.”
4. “Fix the retry bug in `client.ts`; no docs changes.”
5. “Summarize this README so I know what the project does.”
6. “Translate this setup guide into German.”
7. “Create a slide deck from this architecture document.”
8. “Write landing-page copy for our developer platform.”
9. “What does HTTP 429 mean?”
10. “Create a Word document containing this signed contract text.”
11. “Proofread this two-sentence Slack message.”
12. “Review this code for security vulnerabilities.”

## Ambiguous cases to inspect

These can legitimately vary by harness or surrounding task. Check that the agent's decision is sensible rather than forcing a fixed label.

- “Explain the new caching behavior.” Trigger only when the output is intended as documentation or an existing doc is being changed.
- “Add comments to this function.” Trigger when the comments are documentation of contracts or non-obvious rationale; do not trigger for ordinary implementation work with incidental comments.
- “Write a technical report.” Trigger when the report documents a system, procedure, decision, or technical findings for future readers; do not trigger for a general analytical essay with no documentation role.
- “Update the docs and implementation.” Trigger and compose with the relevant coding skill because documentation is a material deliverable.

## Pass criteria

- At least 90% of the clear positive cases trigger across repeated runs.
- At least 90% of the clear negative cases do not trigger.
- Near-miss failures are more important than failures on obviously unrelated prompts.
- Revise the description based on false positives and false negatives, then retest on a held-out set rather than only these examples.
